# 项目工作约定

## 保存位置

- 用户要求所有代理创建的产出保存在 D:\codex，不在 C 盘保存工作产出。
- 本项目根目录：D:\codex\immersive-garden\outputs\Immersive-Garden。
- 本任务交付物放在 D:\codex\immersive-garden\outputs；脚本、草稿、下载和中间文件放在 D:\codex\immersive-garden\work。
- 新任务使用 D:\codex\<任务名>\outputs 和同级 work。D 盘目录未获写入权限时先申请权限，不退回 C 盘保存。
- 迁移或删除已有文件、迁移应用日志和缓存属于单独操作；不要把此约定说成已迁移应用自身数据。

## 当前项目技术约束

- 当前为原生 HTML / CSS / JavaScript、Three.js、WebGL、Vite 项目，未使用 React 或 Vue。
- 实际集成前重新检查 package.json、锁文件及源码，不以此处快照替代检查。
- 不为引入一个组件擅自改变整体技术栈，不无故初始化 React、Tailwind 或覆盖 Vite 配置。
- 用户要求各场景以居中的 logic 作为贯穿元素，可改变其表现形式；维护已有封面展开、鸟的交互、场景切换和返回操作。

- 手动复制同样必须通过技术栈、依赖和授权检查；复制 React 文件不会自动使其变成原生组件。
- 项目公共组件建议放在 src/components/<组件名>/。保留官方源码、独立样式以及必要的最小适配层；不为存放规范建立空组件或预装组件全集。

## Motion 动画引擎接入与长期使用规范

### 1. 定位与官方资料

Motion 纳入本项目长期动画引擎选型，主要负责网页元素的运动、交互和过渡。纳入规范不代表已经安装，也不要求替换所有既有动画。

- 官网：https://motion.dev/
- 官方文档：https://motion.dev/docs
- 原生 JavaScript 快速开始：https://motion.dev/docs/quick-start

使用时查阅最新官方 JavaScript 文档及所选版本的接口，不默认进入 React 文档，不凭记忆使用旧 Motion One、Framer Motion 或其他版本的接口。网络或文档不可用时明确说明未验证内容，不臆造 API。

### 2. 适用范围

1. 基础动画：淡入淡出、移动、缩放、旋转。
2. 滚动动画：滚动触发、进度联动、视差。
3. 鼠标与指针交互：悬停、点击、拖动、跟随；按实际设备区分鼠标和触摸。
4. 弹性动画：Spring、惯性、自然回弹。
5. 页面与界面过渡：页面切换、菜单展开、弹窗。
6. 时间轴：多个元素依次、同步或交错执行。
7. SVG：路径、形状和其他矢量元素动画。

### 3. 技术兼容与按需安装

- 保持当前原生 HTML / CSS / JavaScript + Three.js + Vite 技术栈，优先使用 Motion 原生 JavaScript API。
- 不为 Motion 引入 React，不默认使用 motion/react、React hooks 或 JSX，不擅自更换框架或构建工具。
- 安装前检查 package.json、锁文件、已有 Motion 包及使用位置，避免重复安装。仅在具体需求确有必要且不存在可复用实现时增加 npm 依赖。
- 官方 JavaScript 快速开始使用 motion 包。将来需要安装时，先核实最新官方方式和版本兼容性，再使用现有包管理器；npm 项目的基本命令为 npm install motion。本次不得执行该命令。
- 原生入口示例为 import { animate, scroll } from "motion"。这只是官方调用入口参考，不表示本项目当前已经安装、导入或运行 Motion。
- 保留锁文件和可复现依赖；不要在生产页面随意引入浮动 latest CDN 版本，不同时通过 npm 和 CDN 重复加载同一引擎。
- 项目已有 GSAP、Lenis、CSS 动画及原生 requestAnimationFrame 实现。先检查它们是否已满足当前需求，不因新增此规范批量迁移、卸载、重写或安装新的动画系统。

### 4. 实现选择原则

- 简单悬停、颜色变化和基础过渡：优先 CSS，不为小效果引入复杂方案。
- 复杂连续动画、滚动联动、时间轴和 Spring：优先考虑 Motion；已有可靠实现时先复用，避免重复依赖。
- 粒子、复杂鼠标跟随及画布效果：按需求使用原生 JavaScript、Canvas 或现有 Three.js / WebGL 管线。Motion 可以控制合适的参数，但不替代渲染引擎。
- 动画触发器与动画表现分开管理；重复进入、快速连续点击、中途反向及返回必须有清晰状态，不让多个执行实例相互覆盖。
- 已有组件自带动画时优先保留其官方实现，不再套一层重复动画。
- 当前封面是单屏交互，不因为支持滚动动画而擅自改成滚动网站；是否增加滚动场景由实际需求决定。

### 5. 性能、体验与清理

1. 避免不必要的高频更新和长期运行的不可见动画，防止多个独立动画循环重复处理同一任务。
2. 优先使用 transform、opacity 等通常较友好的属性；滤镜、大阴影、遮罩和尺寸动画按实际设备测量，不把“支持某属性”理解为“没有性能成本”。
3. 注意移动端帧率、GPU 占用、触摸与鼠标差异，不能让只有 hover 才能触发的效果阻断触屏操作。
4. 支持 prefers-reduced-motion；提供减少位移、减少摆动或直接完成切换的等价路径，保留必要反馈和键盘可达性。
5. 每个元素或对象的同一属性同一时刻由一个动画系统负责。避免 CSS、Motion、GSAP 和原生循环同时写 transform、opacity 或同一 Three.js 参数；需要组合时隔离容器或明确控制权移交。
6. 组件销毁或离开场景时，依据当前 API 清理动画控制器、滚动订阅、手势监听、定时器和渲染回调。不要未经核实就统一调用假定存在的清理方法。
7. 重新进入场景应恢复正确状态，不累积事件或重复动画。不要为了视觉效果牺牲页面流畅度。
8. 和现有 WebGL 场景协同时，控制参数与实际渲染协作，避免为 Motion 再建立一套重复的画布渲染循环。

### 6. 与 React Bits、Uiverse 的协同

本节补充此前的资源分工，不覆盖、删除或放宽它们的源码、授权、兼容性及实际集成要求：

- React Bits：优先寻找现成的高级动画组件和视觉特效。
- Uiverse：优先寻找轻量 UI、按钮、卡片、背景图案及其他界面组件。
- Motion：负责确有需要的动画控制、滚动联动、手势交互和过渡。

先查能直接满足需求的已有或官方组件，再判断是否需要额外动画控制。可用 Motion 为静态组件增加交互，也可组合资源，但不要重做组件已有动画或引入不必要依赖。保持整个网站的节奏、缓动、弹性和动效强度统一，遵循用户指定的视觉方向。
